01
行业背景：2026 年，你在浪的哪个位置
不是在等风来，风已经来过一轮了

2023 年 ChatGPT 出现，2024 年 RAG + 基础 Agent 铺开，2025 年多模态 Agent 和 Agent 平台化爆发，2026 年行业已经进入复杂 Agent 时代。Manus、Claude Code、Devin 这类能自主完成多步复杂任务的产品已经是标配，「AI 帮你写一段文案」这种用法早就不够看了。

现在行业真正在讨论的是三件事：Complex Agent（多步骤、多工具、自主规划的智能体）、Context Engineering（如何精细设计 AI 接收的上下文，决定它能不能真正理解任务）、Harness Engineering（如何搭建测试框架、Eval 流水线、沙箱环境，让 Agent 可靠地大规模运行）。这三个词不会在面试里必考，但如果你能聊清楚，面试官会直接刮目相看。

对入行新人的影响：门槛比 2023 年高了不止一个量级，但对有计算机背景的同学是利好——纯业务 PM 愈发难做 AI 产品，技术背景理解 Agent 架构、Eval 设计的壁垒，越来越值钱。

2026 核心趋势

Complex Agent 时代

单轮问答已经是基础功能。主流产品在做的是：多步规划、跨工具调用、长时间任务自主执行，错误自我修复。PM 要能设计 Agent 的 Fallback 机制和边界处理。

新兴关键词

Context Engineering

「给 AI 什么信息、怎么给、给多少」已经成为专门的工程领域。PM 需要理解 System Prompt 设计、Memory 分层、上下文压缩策略对产品效果的直接影响。

可靠性要求

Harness Engineering

Agent 规模化落地的核心挑战：如何让它稳定、可测试、可回滚。Eval pipeline、沙箱隔离、异常监控——这些原本是工程师的事，PM 现在也要参与设计。

💡
2026 年的门槛分水岭：会用 AI 工具 ≠ 能做 AI 产品。现在的要求是——你能不能独立设计一个 Agent 的完整行为边界，包括它什么时候该停、什么时候该问人、出错了怎么兜底。这套思维，是 AI PM 和传统 PM 最本质的差距。
02
AI PM 岗位全景分类
从 Agent 到具身智能，你在哪个赛道上？

先说薪资：2026 年 AI 产品岗位的应届生薪资普遍在 15k–25k 之间，对比传统互联网产品岗位确实可观。头部大厂（字节/阿里/腾讯）可达 25–35k，顶尖 offer 能到 40w+ 年包。

AI 产品方向的岗位名称五花八门，新人容易搞混。按入门难度从低到高排序，大致可以分为以下几类：

岗位类型 核心工作内容 技术要求 适合路径
AI 模型运营 / 数据运营 门槛最低 · 推荐新人 负责模型效果的持续优化，包括：数据标注质量管理、SFT 数据收集策略、RLHF 人类反馈收集、模型上线后的 Bad Case 分析与迭代。 理解数据标注流程、评测指标（ROUGE/BLEU/人工打分）、基础统计 对模型感兴趣但技术背景一般的同学的好选择
AI 应用产品经理 最常见入口 基于现有大模型（GPT/Claude/自研）设计具体应用产品，如 AI 写作、AI 客服、AI 搜索。核心是场景挖掘 + Prompt 设计 + 交互体验。 理解 Prompt Engineering、基础 RAG 概念、API 调用逻辑即可 传统 PM 转型首选，实习生主流岗位
RAG 产品 / 知识库产品 B端核心 基于 RAG（检索增强生成）架构做企业知识库、文档问答、私有数据 AI 化。核心问题：召回质量、分块策略、上下文拼接、幻觉控制。 理解 Embedding、向量数据库（Milvus/Pinecone）、Reranker、Chunking 策略 企业服务/SaaS 公司的主流 AI 产品方向
Agent 产品经理 当前热门 设计能自主规划 + 执行任务的 AI Agent 产品，如 Manus、Devin、Cursor。需要设计任务分解逻辑、Tool Calling 策略、多 Agent 协作架构、异常处理机制。 理解 ReAct 框架、Function Calling、Memory 机制、Workflow 编排 2026 年最火赛道，技术 PM 优势明显
模型产品经理 门槛较高 为大模型本身做产品设计，包括：模型能力规划（推理/代码/多模态）、模型 API 产品化、Benchmark 定义、模型评测体系设计。 需要深入理解模型训练流程、RLHF、Tokenizer、Eval 体系，最好有 NLP 背景 研究院/大厂模型团队，需要技术或研究背景
具身智能产品经理 早期阶段 为机器人/物理 AI 做产品设计，如智能家居机器人、工业机器人、自动驾驶场景下的产品。需要理解感知-规划-执行全链路。 需要机器人学、计算机视觉、传感器融合背景，门槛极高 仍在早期，建议先打好 AI PM 基础再考虑
世界模型 / 多模态产品 前沿研究向 围绕视频生成、3D 理解、世界模型（如 Sora 类产品）做产品化设计。更接近研究院产品方向，少量大厂设置此类岗位。 多模态模型原理、Video Generation、3D 重建基础知识 OpenAI/Pika/Kling 等，暂时不是普通实习生目标
✅
新人建议：优先瞄准「AI 应用产品经理」和「Agent 产品经理」的实习机会，这两个方向门槛相对友好，成长速度快，且和主流市场需求吻合。RAG 方向在 ToB 公司大量开放实习。
03
ToB vs ToC：两种截然不同的 AI 产品世界
选错方向会浪费大量时间，先搞清楚你适合哪个

ToB 业务到底在做什么？一句话：把 AI 能力嵌入企业的日常工作流程，让公司花更少人力、出更少错误、跑得更快。企业买 AI 产品的核心逻辑只有一条——ROI（投入产出比），能省多少钱、能提升多少效率，必须算得清楚。

ToB AI 产品一般覆盖这几类场景：

客服 / 支持

AI 客服 & 坐席助手

替代或辅助人工客服，自动回答常见问题、总结对话、生成工单。金融、电商、运营商是主战场。核心难点：意图识别准确率、拒识策略、人机协作切换时机。

知识管理

企业知识库 & 文档问答

把企业内部文档（手册、合同、政策）向量化，员工用自然语言提问即可得到准确答案。典型产品：飞书 AI 知识库、印象笔记 AI。核心难点：RAG 召回质量、幻觉控制。

销售 / 营销

销售 Copilot & 营销自动化

帮销售自动写跟进邮件、总结客户画像、生成话术建议；帮市场批量生成物料、A/B 测试文案。典型：Salesforce Einstein、飞书销售助手。

法务 / 合规

AI 合同审查 & 风险识别

自动扫描合同条款、标记风险点、生成审查报告。律所和大型企业法务部门是核心买家。准确率要求极高，错漏成本直接是法律风险。

人力资源

AI 招聘 & HR Copilot

简历筛选、面试题生成、入职材料自动化、员工问答机器人。HR 场景数据敏感，隐私合规是重要设计约束。

数据分析

Text-to-SQL & 数据 Copilot

业务人员用自然语言提问，AI 自动生成 SQL 查询并返回图表。让非技术人员也能自助分析数据，减少对数据团队的依赖。

🏗
ToB AI 产品的典型交付形式：SaaS 订阅（最轻）→ API 接入（中间层）→ 私有化部署（最重，金融/医疗/政府必选）。PM 需要理解不同部署形式对产品架构、数据隔离、运维成本的影响。

🏢 ToB AI 产品

代表公司字节飞书、钉钉、百度智能云、阿里云、MiniMax
典型产品AI 客服、企业知识库、AI 合同审查、销售 Copilot、Text-to-SQL
用户决策采购由决策层 / IT 主导，周期 3–12 个月，签单后才能用
成功标准ROI 可量化：人力成本下降 X%、处理效率提升 X 倍
PM 核心能力行业流程理解 + 方案抽象 + 技术落地 + 客户沟通
数据特点私有数据为主，私有化部署常见，RAG 是标配能力
新人难度需深入理解某一行业（金融/医疗/制造），壁垒高回报高

📱 ToC AI 产品

代表产品Claude / Gemini / ChatGPT（通用助手）
Kimi / 豆包（国内 C 端）
Claude Code / Cursor（开发者工具）
阿里阿福医生（垂直 C 端）
典型方向AI 对话助手、AI 编程工具、垂直场景助手（医疗/教育/法律）、AI 搜索
用户决策个人用户随时决策，留存 / 次日留存是核心指标
成功标准DAU、Retention、感知体验，「哇」的瞬间驱动传播
PM 核心能力用户洞察 + 交互体验 + 增长思维
数据特点公域数据为主，大模型直接调用，Prompt 优化是关键
新人难度入门相对快，但竞争激烈，产品直觉和审美很关键
⚠️
关键差异总结：ToB 的 AI PM 更像「方案设计师」——理解客户流程，把 AI 嵌进去；ToC 的 AI PM 更像「体验设计师」——让每个用户都感受到 AI 带来的「超预期」。两者对 AI 技术的理解深度要求相近，但场景思维差异很大。
04
AI PM 核心能力图谱
哪些是必须有，哪些是加分项
基础能力（必须达标）
需求分析 & 文档撰写 用户调研与访谈 数据分析思维 产品逻辑与流程图 Prompt Engineering 基础 LLM 基础原理认知 表达与沟通协作
AI 技术理解（差异化竞争力）—— 点击展开了解
RAG 检索增强生成 ▸
把外部文档切片存入向量数据库，用户提问时先检索相关片段再交给大模型生成回答。解决模型「不知道你公司内部信息」的问题。ToB 知识库产品的核心架构，必须搞懂。
Agent 智能体 ▸
2026 年已是 Complex Agent 主流时代。Agent 不只回答问题，而是自主拆解任务、调用工具（搜索/代码/API/浏览器）、多步执行、自我纠错直到完成目标。Manus、Cursor、Claude Code 都是典型产品。PM 核心工作是设计 Agent 的边界：什么时候停、什么时候问人、失败了怎么兜底。
Function Calling 工具调用 ▸
大模型识别到用户意图后，输出结构化的函数调用指令（而不是纯文字），外部系统执行函数并把结果返回给模型。Agent 能调用真实工具的基础能力。PM 需要理解它的触发逻辑和异常处理。
Fine-tuning 微调 ▸
用特定领域的数据对预训练模型进行二次训练，让模型更擅长某类任务（如法律文书、医疗诊断）。成本比训练基础模型低很多，但仍需大量标注数据。区分「什么时候该微调 vs 用 RAG」是 PM 常见判断题。
向量数据库 Vector DB ▸
把文本/图片转成高维数字向量存储，支持「语义相似度」检索（不是关键词匹配）。RAG 的底层存储层，常见产品有 Pinecone、Milvus、Chroma。PM 需要理解它与传统数据库的核心差异。
Prompt / Context Engineering 2026 核心技能 ▸
Prompt Engineering 是基础——设计 System Prompt、Few-shot 示例、思维链引导。2026 年更进一步的是 Context Engineering：精细设计 AI 完整输入的上下文，包括记忆结构、工具文档、历史对话压缩策略，决定 Agent 能不能真正理解任务。这已经是专门的工程领域，AI PM 必须深度掌握。
Eval / 评测体系 模型评估 ▸
系统性衡量 AI 输出质量的方法，包括自动化指标（ROUGE、准确率）和人工评测（打分、对比）。PM 负责定义「什么是好的输出」，并推动工程团队建立 Eval pipeline，是推动模型持续优化的关键。
Harness Engineering 2026 新兴必知 ▸
让 Agent 可以大规模、可靠地运行的工程体系：Eval 自动化流水线、沙箱隔离环境、异常监控 + 回滚机制、任务执行日志追踪。2026 年 Agent 落地的核心挑战不是「能不能做到」，而是「能不能稳定、可测试地做到」。PM 不需要自己搭，但必须理解它为什么重要，才能和工程团队有效对齐。
多模态 Multimodal ▸
模型能同时理解和生成文字、图片、音频、视频等多种形式的内容。GPT-4o、Gemini 1.5 是典型多模态模型。PM 需要理解不同模态能力的边界，以及产品中何时需要引入多模态。
Workflow 编排 流程自动化 ▸
把多个 AI 调用 + 外部工具串联成一个自动化流程，如「邮件进来 → AI 分类 → 调用 CRM 查客户 → 生成回复草稿 → 发送」。Dify、n8n、Coze 是主流编排平台。PM 设计这类产品需要流程图思维。
工具能力（亲手用过才算数）—— 点击展开了解
Figma 设计原型 ▸
行业标准原型工具，做线框图/交互稿，国际通用，AI PM 必会。免费版足够学生使用，重点掌握：Frame、Auto Layout、Components、Prototype 连线。面试带上作品集链接是加分项。
Pixso 设计原型 ▸
国产 Figma 替代，国内团队常用，支持中文协作，功能基本对齐。优势是服务器在国内，访问更稳定。适合不想折腾 Figma 网络问题的同学。
Cursor AI 编程 ▸
AI 代码编辑器（基于 VSCode），能用自然语言写代码/改 Bug，PM 用来做 Demo 项目首选。优势是理解整个项目上下文，不是单次问答。新手能用它做出真实可运行的小项目。
Claude Code AI 编程 ▸
Anthropic 官方 CLI 编程助手，终端直接调用，支持复杂代码库理解。适合需要在命令行工作的场景，能直接操作文件、运行命令、调试代码。
Trae AI 编程 ▸
字节跳动出品 AI IDE，新人搭个人主页/小项目的低门槛选择。特点是对中文支持好，模板丰富，适合零基础快速出成果。用它做的项目可以直接部署到 GitHub Pages。
Claude AI 助手 ▸
Anthropic 出品，长文本理解 + 写作分析能力强，PM 日常必用。优势是 200k token 上下文窗口，能处理长文档；输出质量稳定，适合做产品分析、写文档、设计 Prompt。
Gemini AI 助手 ▸
Google 出品，多模态能力突出，与 Google Workspace 深度集成。适合处理图片、PDF、长文档。Gemini 2.0 的 Flash 模式响应速度快，适合快速探索想法。
Manus AI 助手 ▸
国内 AI Agent 产品，自主完成多步任务，体验它来理解 Agent 产品形态。用它做几个真实任务（整理文件、写报告、查资料），能帮你建立对 Agent 能力的第一手认知。
Dify / Coze 低代码平台 ▸
AI 应用低代码搭建平台。Dify 开源可私有部署，Coze 字节出品更易用。适合快速搭建 AI 助手原型，支持接入微信、飞书等渠道。PM 用来验证想法非常高效。
Python 基础 编程能力 ▸
不需要成为工程师，但要能看懂代码、调 API、写简单脚本。重点掌握：变量、函数、列表/字典、基础 IO。能用 Python 调用 OpenAI/Claude API 做小工具是加分项。
SQL 基础 数据查询 ▸
基础查询能力即可：SELECT、WHERE、GROUP BY、JOIN。PM 常用它从数据库拉数据做分析、验证产品假设。不需要懂复杂优化，能写出正确的查询逻辑就行。
Notion / 飞书 文档协作 ▸
文档和知识管理工具。Notion 国际化团队常用，飞书国内更普及。PM 的日常：写 PRD、记录会议、整理需求池、做产品 Roadmap。熟练使用能大幅提升工作效率。
关于「要不要做 Demo」——必须做，按难度选一个路径：
入门 · 推荐

Claude 轻量搭建

用 Claude 设计 Prompt + 对话流程，截图录屏展示交互逻辑。零代码，1 天可完成，重点展示产品思路而非技术实现。

进阶 · 有亮点

Trae 做个人主页

用字节 Trae（AI IDE）让 AI 写一个个人简历网站，部署到 GitHub Pages。不需要前端基础，过程本身就是 AI 编程工具的第一手体验，面试时有话讲。

高阶 · 强加分

Cursor / Claude Code

做一个真实可运行的小项目（RAG 问答 / Agent 工具）。门槛较高，但完成后直接证明你具备技术协作能力，是 AI PM 里的稀缺素质。

📌
核心原则：工具必须亲手用过，不能只看别人演示。哪怕 Trae 做出来的网页很简陋，面试时说「我用 Trae 自己搭了个人主页，踩了这几个坑」——比背 10 篇 AI 文章更有说服力。亲手用过 > 看过 > 听说过。

不是「注册一下试试」，而是高频深度使用，形成真实感受：

  • 用 Claude / ChatGPT / Gemini 做真实工作（写报告、做分析、整理笔记），感受能力边界和失败场景
  • 用 Kimi / 豆包 体验国内产品的设计取舍，和国际版对比，想清楚为什么不一样
  • 试用 Claude Code 或 Cursor 完成一个小任务（哪怕让它帮你写个脚本），感受 AI 编程工具和普通聊天的差异
  • 用 Trae 搭一个个人简历网页——不要求好看，要求你亲手做完整个过程
  • 关注行业动向：订阅「AI 产品新知」「硅星人」「量子位」，每天 10 分钟刷行业信息，能独立讲清楚最近 2–3 个 AI 产品热点
第二步（同步进行）
用 AI 经验包装简历

你大概率没有「正式 AI 产品经历」，但这不是问题——关键是把现有经历重新包装，让面试官感受到你的 AI 思维：

  • 挖掘已有项目里的 AI 视角：做过用户调研？写成「验证 AI 功能需求的用户访谈」。写过分析报告？加一句「运用 AI 工具提升效率 40%」。做过运营活动？提炼「数据驱动 + AI 辅助决策」的逻辑
  • 补充一个真实的 AI 实践项目：用上一步做的 Demo 或 Trae 主页，写成简历项目条目——「独立完成 XX AI 工具的产品设计与原型验证，核心功能为…」
  • 简历措辞：主动用「Prompt 设计」「AI 产品体验评测」「LLM 应用场景探索」等关键词，这些词在 JD 里高频出现
  • 简历不超过 1 页，项目部分每条都要有动词 + 数字 + 结果，不要堆职责描述
第三步
投递 + 面试准备
  • 大厂走校招系统，AI 创业公司直接 Boss直聘 / 脉脉私信 HR 或 PM，附上简历+一句话说清「我为什么适合这个岗位」
  • 准备 3 分钟自我介绍，必须包含：你用过哪些 AI 产品、你做过什么和 AI 有关的事、你为什么想做 AI PM
  • 准备面试高频题：「说一个你觉得体验不好的 AI 产品，你会怎么改」「你理解的 RAG 是什么，举一个场景」「如果让你设计一个 AI 功能，你从哪里开始」
  • 找一个有 AI 行业经验的人做一次模拟面试，比自己背题有效 10 倍
关于两段实习叠加
专注 > 叠加，质量比数量重要

第一次实习强烈建议专注一段。AI PM 实习的真正价值不是「完成工作量」，而是深度参与一个产品的完整迭代周期，这需要你全身心沉进去。分心叠加反而两段都浮浅，面试时也说不出有深度的东西。

实习结束后有剩余时间，再考虑第二段或延期转正。时间安排上确实冲突，果断放弃节奏更差的那段——机会还会有，第一段留下好口碑才是关键。

06
常见误区 & FAQ
新人最容易踩的坑
误区 我没有技术背景，AI PM 是不是没戏？
不是。AI PM 不需要你会写模型代码，但需要你「理解技术边界」——知道哪些事 AI 能做、做到什么程度、为什么失败。这部分通过 3–6 个月的主动学习完全可以达到工作水准。关键是要有主动学习的意愿，而不是等别人教。
误区 AI PM 是不是要选头部大厂才值？
不一定。AI 创业公司（30–200人规模）往往能给你更大的产品责任、更快的迭代节奏、更直接的用户反馈。大厂胜在品牌背书和系统化培训。建议：如果有腰部到头部的 AI 创业公司 offer（如 MiniMax、月之暗面、智谱等），不一定比字节的实习差。
建议 暑期实习选 ToB 还是 ToC？
取决于你的长期方向。如果你对「用户体验 / C 端增长 / 消费者洞察」感兴趣——去 ToC；如果你对「行业理解 / 企业数字化 / 解决方案架构」感兴趣——去 ToB。两个方向都不要只图「听起来好听的名字」，要看自己做起来哪个更有劲。不确定的话，第一段实习选 ToC，因为体感更直接，更容易建立对 AI 产品的基础感觉。
建议 准备阶段绝对不能忽略的事
① 持续体验 AI 产品——每周至少深度体验 1 个 AI 产品并写 200 字感想，积累到面试时能随口讲出 5–6 个有见解的案例。
② 建立你的「AI 信息流」——关注：AI 产品 Daily（公众号）/ 硅星人 / 36氪 AI 板块 / Twitter 的 AI KOL，保持每日信息摄入。
③ 做真实的事情——哪怕用 Dify 做一个自用的 AI 助手，也比读 10 篇文章更有价值。Doing > Reading。
