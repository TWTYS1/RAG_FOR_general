二、为什么这样设计 — AI PM 视角

2.1 核心矛盾

传统方案致命问题
手动翻阅 PDF/DOCX一个 3GPP meeting 产出上百份 TDoc，人工不可能穷举
Ctrl+F 关键词搜索"remaining issue" 搜不到 "FFS"、"not agreed"、"pending"
ChatGPT + 附件数据安全风险、token 成本高、无法自动溯源 TDoc 编号
商业 RAG 产品不识别 3GPP 文档结构（TDoc/WG/CR），无法做标准缺口分析

2.2 技术选型推演

Layer 1: 文档解析
  评估: pdfplumber / python-docx / BeautifulSoup / markdown-it
  策略: DOCX 优先（3GPP 主力格式），按 Word heading style + 3GPP 元数据正则
  输出: heading_path + TDoc编号 + WG + Meeting + CR + 公司 + 表格

Layer 2: 文本分块
  评估: 固定字数 / 段落 / 语义相似度 / 标题层级感知
  策略: DOCX → heading-path 优先切分，保留完整层级路径
        chunk=800 tokens, overlap=150
        含 "remaining issue" 等关键词的段落 → 生成额外 boost 副本

Layer 3: 向量模型
  评估: OpenAI text-embedding-3 / BGE-M3 / Qwen3-Embedding-0.6B
  策略: Qwen3-Embedding-0.6B, 1024维, 本地 GPU 推理
        多语言能力强（中文→英文跨语言检索适用）

Layer 4: 向量数据库
  评估: Pinecone / Weaviate / FAISS / ChromaDB + BM25
  策略: ChromaDB (dense) + 内存 BM25 (sparse)
        RRF 融合，TDoc/CR 编号精确加权

Layer 5: 查询处理
  中文 query → 4 variant:
    a) 原 query  b) 英文翻译  c) 3GPP 术语扩展  d) 关键词列表

Layer 6: 生成
  评估: GPT-4 / Claude / DeepSeek
  策略: DeepSeek API + 3GPP 结构化回答模板
        每个结论至少引用 1 个 chunk，证据不足时明确声明

2.3 关键设计决策

决策理由取舍
本地 Embedding + 云端 LLM 数据安全 + 智能上限 需 GPU / ~1.2GB 显存
1024 维（非 2048） 召回差异 <2%，存储减半 接受微小精度损失
Dense + BM25 混合 3GPP 固定术语需精确匹配 维护两套索引
50→15 召回→重排 初召回宽泛确保覆盖，精排保质量 增加 ~100ms 延迟
DOCX heading-path 优先切分 3GPP 文档有明确章节结构 对无结构文档回退段落分割
关键词 boost 副本 "remaining issue" 等为专利挖掘关键信号 索引体积增加 ~15%

五、检索策略

5.1 跨语言查询扩展

中文 Query扩展结果
"还有哪些未解决问题" remaining issue, open issue, unresolved issue, FFS, for further study, not agreed, pending issue, way forward
"高层参数" higher layer parameters, RRC parameters, LPP parameters, NRPPa IE, NGAP IE, configuration parameters
"gNB侧模型" gNB-sided model, gNB-side model, NG-RAN node assisted positioning, Case 3a
"数据采集流程" data collection, measurement collection, OAM triggered reporting, UE measurement report, data gathering

5.2 Hybrid Search 融合算法

RRF (Reciprocal Rank Fusion)：

score(doc) = Σ 1/(k + rank_i(doc))

其中 k=60，rank_i 是第 i 个检索器（dense / BM25）中该文档的排名。

额外加权：

  • TDoc 编号精确匹配 → ×2.0
  • CR 编号精确匹配 → ×2.0
  • Spec 编号精确匹配 → ×1.5
  • "remaining issue" / "open issue" / "FFS" 命中 → ×1.3
  • "way forward" / "conclusion" 命中 → ×1.2

5.3 Rerank 因子（50 → 15）

因子权重说明
semantic_score0.30Dense vector 余弦相似度
keyword_score0.253GPP 关键词命中数
metadata_match0.20WG/meeting/rel 与 query 的匹配度
freshness0.15文档 meeting 日期越新分越高
completeness0.10是否包含 conclusion / way forward / remaining issue
