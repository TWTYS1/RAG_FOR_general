RAG 问答系统

多格式文档混合索引 · 本地语义检索引擎

RAG 多格式解析 向量检索 LLM ChromaDB

1. 项目概述

1.1 一句话定义

构建一个多格式文档混合索引的本地 RAG 问答助手。将 React 官方文档、个人笔记、PDF 电子书、导出的网页等统一接入，用户用自然语言提问，系统自动检索相关片段，交由 LLM 生成带来源引用的回答。

1.2 支持的文档格式

格式典型来源解析难度MVP 阶段
.md Markdown React/Vue 官方文档、Notion 导出、个人笔记 ⭐ 低 Phase 1 首发
.pdf PDF 电子书、论文、产品手册、合同 ⭐⭐⭐ 中高 Phase 1 首发
.txt 纯文本 日志、配置文件、导出数据 ⭐ 低 Phase 1 首发
.html 网页 文档站离线镜像、网页存档 ⭐⭐ 中 Phase 2 追加
.docx Word 团队文档、PRD、会议纪要 ⭐⭐ 中 Phase 2 追加

1.3 业务场景（A + C 混合）

场景用户痛点本系统如何解决
A · 技术文档 前端开发者 / 团队新人 React 官方文档上千页，遇到问题翻文档效率低；GPT 回答可能过时或幻觉 语义搜索 → 精准定位文档段落 → LLM 基于真实文档生成回答，杜绝幻觉
C · 个人知识库 学习者本人 学习笔记散落各处（Markdown/PDF 电子书/导出的网页），看过就忘，格式五花八门 多格式统一接入 → 混合索引 → 提问时跨格式同时检索

1.4 核心价值

  • 多格式统一：无论原始文档是 Markdown、PDF、Word 还是网页，统一解析→统一分块→统一检索，用户无感
  • 可信：每个回答都附带来源文档路径、文件类型和页码/章节，点击即可验证
  • 可控：数据在本地，不依赖云端索引，随时可增量更新文档库
  • 可演进：策略模式设计，新增文件格式只需添加一个 Parser 类，不影响现有代码

3. 核心执行逻辑

3.1 文档预处理流水线（离线）

1递归扫描 docs/，收集所有支持格式
2FileTypeRouter 判断格式，路由到对应 Parser
3各 Parser 提取纯文本 + 保留结构信息
4统一 SemanticChunker 切分为 chunk
5每个 chunk → Embedding API 生成向量
6向量 + 元数据写入 ChromaDB

⏱ 预计时间：React 文档 + PDF 电子书 + 笔记混合，约 2000-3000 个 chunk，Embedding API 并行调用 5-10 分钟

3.2 分块策略——按文件类型差异化

文件类型分块方式chunk_sizeoverlap说明
Markdown 按 H2/H3 标题语义切分 ~500 tokens 100 tokens 利用 AST 解析标题层级，保证每个 chunk 是一个完整的知识点
PDF 按页码 + 段落滑动窗口 ~500 tokens 100 tokens PDF 无标题结构，按页切后滑动窗口保证跨页内容不断裂
Word 按段落 + 标题样式 ~500 tokens 100 tokens 优先识别 Heading 样式作为切分点，无样式则按段落滑动
HTML 按 h1-h6 标签 + section ~500 tokens 100 tokens 利用 DOM 结构，原理同 Markdown
纯文本 按空行 + 滑动窗口 ~500 tokens 100 tokens 双换行作为自然段落边界，超出上限则滑动切分

3.3 在线问答流程

1用户输入自然语言问题
2Query → Embedding 向量化
3ChromaDB 语义检索 Top-K（k=8）
4Metadata 过滤（可选：限定文件类型）
5组装 Prompt：System 指令 + Context + Query
6调用 LLM 生成回答（带来源引用 + 格式标签）
7格式化输出：回答 + 引用来源

3.4 Prompt 设计

## System Prompt
你是一个技术文档助手。请严格基于下方提供的文档片段回答问题。
文档来源可能包含多种格式（Markdown/PDF/Word/网页等）。
如果文档片段不足以回答，请明确说"当前文档库未覆盖此问题"。
回答时在关键信息后标注来源编号，如 [1]、[2]。

5. 分阶段实施计划

阶段目标具体任务预估时间
Phase 0 环境搭建
  • pip install chromadb openai tiktoken markdown-it-py pdfplumber python-docx beautifulsoup4 lxml python-dotenv streamlit
  • 配置 .env（OPENAI_API_KEY / DEEPSEEK_API_KEY）
  • git clone React 文档到 docs/react-docs/
  • 放入 PDF 电子书到 docs/ebooks/、个人笔记到 docs/my-notes/

Phase 1 多格式解析器 + 预处理管道
  • 实现 FileTypeRouter（扩展名 + MIME 检测 → 路由到对应 Parser）
  • 实现 BaseParser 抽象基类（统一接口：parse() → List[Document]）
  • 实现 5 个解析器：Markdown、PDF、Word、HTML、纯文本
  • 实现 SemanticChunker（按文件类型选择分块策略）
  • 实现 Embedding 调用 + 批量错误重试
  • 实现 ChromaDB 写入（metadata：来源路径、文件类型、标题/页码）
  • 运行 ingest.py 完成首次全量索引
 2 小时
Phase 2 检索 + 生成链路
  • 实现检索模块：Query 向量化 + ChromaDB.similarity_search()
  • 支持 metadata 过滤（如只搜 PDF、只搜个人笔记）
  • 实现 Prompt 组装 + LLM 调用
  • 联调：从输入问题到输出回答的完整链路
 45 分钟
Phase 3 CLI 交互式问答
  • 实现交互式 CLI 循环（/exit 退出，/sources 显示引用，/filter 按格式过滤）
  • 答案格式化输出：文件类型图标 + 来源路径 + 页码标注
  • 边界情况处理：空检索结果、API 超时、无效输入、损坏文件跳过
 30 分钟
Phase 4 Streamlit Web UI
  • Chat 对话界面（对话历史保留）
  • 侧边栏：按文件类型筛选 + 显示检索来源片段
  • 文档上传入口：拖拽上传新文件即时索引
 1 小时
